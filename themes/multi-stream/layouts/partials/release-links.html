{{- /* Every link rule for a release, in one place. The release page header and the cards both read it. Input: dict "page" [ "card" true ] Output: dict (the release date is compared with the build time, so these change on the first deploy after it) services the service logos to show, in the canonical order (release-services.html) presave the pre-save (HyperFollow) URL for a card's "Presave" chip, or "": only on a card and only while unreleased (the release page has the header button instead) button the URL for the release page's one header button, or "": the pre-save page while unreleased, and after release only when there are no service logos to use instead The rules: - `links.streaming` is the HyperFollow page. Before the release it is the Presave chip on a card and the header button on the release page; after it, the button appears only when the release has no other links at all (Listen now). - apple_music_album and itunes_album hold the same Apple ID. itunes_album is set only when the release can be pre-ordered on iTunes, so before the release date a card shows iTunes when it is set and never Apple Music, whose page cannot be played yet. The release page keeps both: it is where a visitor looks for every link. */ -}} {{- $p := .page -}} {{- $links := $p.Params.links | default dict -}} {{- $unreleased := now.Before (time.AsTime $p.Params.release_date) -}} {{- $services := partial "release-services.html" (dict "links" $links) -}} {{- if and $unreleased .card }}{{ $services = where $services "key" "ne" "apple_music" }}{{ end -}} {{- $streaming := $links.streaming | default "" -}} {{- return (dict "services" $services "presave" (cond (and $unreleased .card) $streaming "") "button" (cond (or $unreleased (not $services)) $streaming "")) -}}
